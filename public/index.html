A much stricter teacher.

Work in your local repository. Mercy scans a bounded set of source files without running the application.

Ask. Trace. Review.

Codex or Claude reasons over numbered source excerpts. Mercy’s tools validate citations and save reviewed answers.

3

Explain it back.

Open the offline notebook or ask for a mock viva. Keep digging until the explanation makes sense to you.

One classroom rule:

A citation is a clue, not a test result. Imports don’t prove runtime calls. A CSV doesn’t prove training. Mercy marks what isn’t verified.

05 / THE BACK-OF-CLASS QUESTIONSsomeone was going to ask.

Before you raise your hand.

Is Mercy another chatbot or a new model?

Mercy is a native skill and local evidence toolkit for Codex and Claude Code. Your coding agent supplies the model and reasoning. There’s no additional model server or provider key for this workflow.

Does my code stay offline?

The local CLI scans files without making network requests by default, and generated notebooks work offline. When you use Codex or Claude, the host model sees the source context under its own privacy policy. “Local toolkit” does not mean your host model is offline.

Will it run or change my project?

Ordinary analysis reads source and writes study artifacts. Running the target application, tests, training, databases, deployments or edits to application code requires a separate request. Skill installation writes the selected local skill files.

Can I share the notebook?

Yes, after reviewing it. It contains paths, symbols, routes, scan metadata and reviewed answers. Raw source bodies aren’t embedded by the report exporter, but metadata and explanations can still be private.

Will it guarantee I pass my viva?

No. Mercy helps you investigate and practise. The scanner is bounded, AI explanations can be wrong, and source citations are not runtime verification. You still need to understand, check and demonstrate your own work.
